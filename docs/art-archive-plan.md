# 대규모 작품 아카이브 운영안

작성일: 2026-09-07 / 상위 문서: [프로젝트 기획안](project-plan.md)

작업 순서·담당 역할·단계별 검수·공개와 운영 인수는 [실행 계획](execution-plan.md)을 따른다. 이 문서는 수집 규모·작가 정리·보존 정책의 세부 기준이다.

## 1. 아카이브의 역할

많은 작품을 작가별로 축적하고 제작 시기·재료·소장처·연작의 맥락으로 찾아볼 수 있는 기반을 만든다. 원자료와 이미지, 수정 이력을 보존해 시간이 지나도 다시 확인할 수 있어야 한다.

‘오늘의 작품’은 축적된 아카이브를 소개하는 입구다. 작품의 기본 레코드 공개, 해설 작성, 블로그 발행은 별도의 작업이다. 모든 작품에 장문의 글을 작성해야만 수집·공개할 수 있는 구조는 사용하지 않는다.

현재 확보량은 작품 30점, 확인된 작가 19명, 작가 미상 작품 4점이다. 이것은 검증 표본이다. 아래 수량과 운영 방식은 제안이며 대량 수집·보존 시스템이 이미 구현됐다는 의미는 아니다.

## 2. 규모와 수집 깊이

| 단계 | 제안 규모 | 목적 |
| --- | --- | --- |
| 검증 표본 | 현재 30점 | 작품·작가·출처·이미지의 관계 확인 |
| 시험 수집 | 1,000점 | 수집 속도, 실패 처리, 작가 연결, 중복 검토, 저장량 측정 |
| 첫 공개 | 이미지와 기본 정보가 확보된 약 5,000점, 확인된 작가 100명 이상 | 대량 탐색과 작가별 아카이브 제공 |
| 지속 확장 | 10,000점 이상 | 새로운 작가·기관·지역 추가와 기존 작가 자료 보완 |

수량은 계획 기준이며 이용 가능한 원자료 조사 결과에 따라 조정한다. 기관별 공개 범위, 작가의 실제 작품 수, 이미지 제공 조건에 따라 수집 한계가 다르므로 작가별로 같은 수량을 강제하지 않는다.

우선 작가 20명을 정하고 작가당 20점 이상 확보 가능한지 조사한다. 가능하지 않으면 확인된 범위와 자료가 부족한 이유를 기록한다. 전체 작품 수 외에 ‘작가별 작품 수의 중앙값’, ‘1점만 확보한 작가 비율’, ‘우선 작가별 기관 조사 상태’를 함께 관리한다.

작가 페이지의 ‘전체 작품’은 이 서비스에 등록된 작품 전체를 뜻한다. 전작 목록을 검증한 근거가 없으면 완전한 작품집이나 전작 아카이브라고 표현하지 않는다.

## 3. 작가 아카이브 화면

각 작가는 고정 주소를 갖는다. 이름 검색과 가나다·알파벳 색인으로 접근하고 다음 내용을 제공한다.

| 영역 | 내용 |
| --- | --- |
| 기본 정보 | 한글·원문 이름, 별칭, 확인된 생몰년·활동 지역, 출처 |
| 수집 현황 | 등록 작품 수, 이미지 확보 작품 수, 수집한 기관, 최근 추가일 |
| 작품 목록 | 제작 시기·유형·재료·소장처·연작 필터, 정렬과 페이지 이동 |
| 시기별 보기 | 확인된 제작 연대순 정리; 추정 연대는 범위를 표시 |
| 관련 자료 | 해당 작가를 다룬 블로그, 실제 자료를 제공한 사이트 |
| 범위 안내 | 조사한 기관과 확인일, 아직 검토 중인 자료 범위 |

대표작은 근거가 있는 경우에만 사용하고 운영자 취향으로 고른 작품은 ‘에디터 선정’으로 표시한다. 출생·활동·작품 연대를 혼용하지 않는다. 연대가 없는 작품은 ‘제작 시기 미상’으로 따로 볼 수 있게 한다.

작가 이름의 검색 별칭은 통합하되 원문은 보존한다. 작가 미상은 동일 인물로 묶지 않는다. 공방·추종자·공동 제작·귀속 추정은 원자료의 관계와 확실성 수준을 유지한다.

## 4. 수집과 공개 흐름

1. **기관별 수집 계획**: 공식 API나 제공 데이터의 범위·이용 조건·갱신 방식·접근 한도 확인.
2. **원자료 확보**: 출처 기관, 원문 주소, 기관 식별자, 수집 시각, 원본 응답을 보존.
3. **기본 검증**: 필수 식별정보, 작품 유형, 이미지 주소·형식·크기, 개별 이용 표시 확인.
4. **관계 정리**: 작가 식별자 대조, 기존 작품과 중복 비교, 판본·연작·귀속 구분.
5. **예외 검토**: 이름 충돌, 이미지 불일치, 누락·권리 불명·출처 충돌은 검토 대기.
6. **기본 자료 공개**: 검증을 통과한 작품은 해설 유무와 별개로 공개.
7. **편집 확장**: 일부 작품에 한글 소개·감상 포인트·주제 컬렉션·블로그 연결 추가.
8. **변경분 반영**: 원출처의 변경을 감지하고 이전 값과 변경 이유를 남김.

초기 수집처는 이미 표본을 확보한 The Met과 Cleveland를 우선한다. 다른 기관은 데이터 품질과 이용 조건을 확인한 뒤 추가한다. [The Met 공개 자료](https://www.metmuseum.org/hubs/open-access) · [Cleveland 공식 API 안내](https://openaccess-api.clevelandart.org/)

수집 실행에는 배치 식별자, 대상 범위, 마지막 완료 위치, 성공·실패·검토 대기 수를 남긴다. 같은 범위를 다시 실행해도 중복 등록되지 않아야 한다. 실패 항목만 재시도할 수 있고 출처의 접근 한도를 지킨다. 현재의 30점 수집 스크립트는 이러한 운영 기능을 모두 갖춘 상태가 아니다.

## 5. 무엇을 한 작품으로 셀 것인가

기관과 소장품 식별자를 조합해 원출처 레코드를 식별한다. 내부 작품 ID는 별도로 유지하며 여러 원출처가 같은 물리적 작품을 가리킬 때 검토 후 연결한다.

- 같은 작품의 고해상도 이미지·축소본·부분 사진은 여러 작품으로 세지 않는다.
- 같은 제목의 다른 작품과 판화의 서로 다른 인쇄본은 구별한다.
- 연작·병풍·다폭화의 전체와 부분은 상하 관계를 남기고 집계 기준을 명시한다.
- 동명이인 작가와 공동 제작자는 이름만으로 합치지 않는다.
- 이미지 유사도나 파일 해시는 검토 단서이며 작품 동일성의 최종 판정으로 사용하지 않는다.

공개 작품 수, 이미지 확보 작품 수, 원출처 레코드 수, 이미지 파일 수, 확인된 작가 수를 따로 집계한다. 이미지가 없거나 제공할 수 없는 작품은 ‘정보만 제공’ 상태로 둘 수 있지만 이미지 확보 목표량에는 포함하지 않는다.

## 6. 보존과 기록

| 보존 대상 | 관리 방법 |
| --- | --- |
| 원자료 | 최초 수집 응답과 변경된 원자료, 출처와 수집 시각 보존 |
| 내부 정리 정보 | 원문과 번역·정리값 분리, 수정 전후 값·시각·이유·작업 주체 기록 |
| 이미지 | 출처에서 받은 원본, 화면용 파생본, 파일 해시·형식·크기·원주소·이용 근거 기록 |
| 작품 관계 | 작가·작품의 통합·분리 이력과 이전 주소 연결 보존 |
| 수집 이력 | 기관·배치·성공·실패·대기 상태와 마지막 확인일 기록 |
| 백업 | 데이터와 파일의 별도 사본, 정기 무결성 확인과 실제 복원 검증 |

원출처에서 정보가 바뀌면 내부 값을 조용히 덮어쓰지 않는다. 출처 간 값이 충돌하면 원문을 각각 남기고 대표 표시값의 선택 근거를 기록한다. 제공 중단이나 권리 상태 변경을 발견하면 공개 이미지를 중단·검토할 수 있게 하며, 내부 보존 범위도 해당 조건에 맞춰 검토한다.

공개 페이지에는 원출처와 자료 최종 확인일을 표시한다. 상세 수정 이력은 운영자가 확인할 수 있게 하고, 작가 귀속이나 연대처럼 중요한 정정은 방문자에게도 안내한다.

매일 변경 데이터 백업, 주간 파일 무결성 확인, 월간 표본 복원 검증을 초기 운영안으로 제안한다. 빈도와 보존 기간은 비용·복구 목표에 맞춰 확정한다. 자동 작업은 아직 설정하지 않았다.

## 7. 대량 탐색과 이미지 운영

작품 목록은 기본 24점씩 서버에서 조회하고 다음 페이지나 더보기로 확장한다. 전체 작품 데이터를 브라우저에 한 번에 전달하거나 모든 원본을 목록에서 불러오지 않는다. 검색·필터·정렬 상태는 주소에 반영해 다시 방문하고 공유할 수 있게 한다.

이름·별칭 검색, 작가·시기·유형·소장처·이미지 유무 필터를 조합한다. 추정 연대의 범위가 선택 시기와 겹치는지 판단하는 규칙을 정하고 미상 항목 처리도 명시한다. 실제 공개 규모에서 결과 수와 페이지 간 누락·중복을 검증한다.

보관용 원본과 목록용·상세용 이미지를 구분한다. 긴 병풍이나 세로형 회화의 비율을 유지하고 확대 화면에서 필요한 크기를 요청한다. 원본은 콘텐츠 저장소에 보관하고 코드 배포와 분리한다. 목록의 지연 로딩과 캐시를 적용한다.

현재 표본의 원본 JPEG 합계는 103,475,299바이트이며 30점 평균은 약 3.45MB다. 같은 평균을 단순 적용하면 5,000점은 약 17.2GB, 10,000점은 약 34.5GB다. 이는 원본만의 예시 추정이며 실제 파일 크기, 파생 이미지, 이전 버전, 백업과 전송 비용은 별도로 산정해야 한다.

## 8. 품질 관리와 확대 조건

전체 자료에 자동 검증을 수행하고 기관·작가·유형별 표본과 검증에서 발견한 예외를 사람이 검토한다. 표본에서 반복 오류가 발견되면 해당 범위 전체를 다시 점검한다. 자동 통과와 사람의 원문 대조 완료 상태를 구분한다.

1,000점 시험 운영의 통과 조건:

- 재실행해도 작품·이미지가 불필요하게 중복되지 않는다.
- 수집 중단 후 완료 지점에서 재개하고 실패 목록을 확인할 수 있다.
- 작가 병합·동명이인·미상·공동 제작의 처리 결과가 정확하다.
- 원자료 수정 후 이력이 남고 내부 편집값을 임의로 잃지 않는다.
- 작품·이미지·작가 수를 구분해 집계할 수 있다.
- 백업에서 작품 정보와 이미지를 실제 복원할 수 있다.
- 검색·필터·페이지 이동·확대 감상이 실제 자료로 동작한다.

5,000점 공개 전에는 같은 검증을 실제 수량에서 반복하고 처리 시간·검색 응답·용량·검토 대기량을 기록한다. 30점 검토용 HTML 페이지의 정상 동작을 대규모 서비스의 성능 검증으로 대신하지 않는다.

## 9. 세 콘텐츠의 운영 분담

**아트**는 작품과 작가의 자료를 지속적으로 축적·정리·보존한다. **참고사이트**는 실제 수집처와 추가 조사처를 연결한다. **블로그**는 축적된 자료를 읽고 해석하며 작가와 작품을 소개한다.

아카이브 규모와 편집 발행량은 별도로 계획한다. 작품 수집은 기관별 변경 범위와 운영 여건에 맞춰 배치로 실행하고, 블로그·오늘의 작품은 편집 가능한 분량만 발행한다. 방문자가 대량 자료를 찾아볼 수 있는 깊이와 일부 작품을 친근하게 소개하는 경험을 함께 유지한다.
