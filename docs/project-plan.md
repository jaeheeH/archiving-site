# ARCH-B 최종 프로젝트 기획안

작가별 대규모 작품 아카이브를 중심으로 아트 · 참고사이트 · 블로그를 연결하는 서비스

작성일: 2026-09-07 / 버전: 3.0 / 상태: 최종 기획 정리 완료 · 웹 우선 실행 기준

이 문서는 무엇을 만들고 어떤 경험을 제공할지 정한다. 실제 작업 순서·의존 관계·검수·공개·운영 인수는 [처음부터 운영까지의 작업 계획](execution-plan.md)을 따른다. 수집과 보존의 세부 기준은 [대규모 작품 아카이브 운영안](art-archive-plan.md)에 정리한다. 수량·일정은 실행을 위한 제안이며 실제 구현 완료나 사용자에게 확정받은 계약 수치를 뜻하지 않는다.

**첫 공개의 중심은 충분한 작품과 신뢰할 수 있는 작가 아카이브다.** 기본 자료 축적과 오늘의 작품·해설·블로그 편집을 별도 주기로 운영한다. 웹 우선은 이번 최종안에 반영한 방향이며, 수량·공수는 시험 수집으로 검증할 계획값이다.

## 1. 프로젝트 개요

**많은 작품을 작가별로 수집·정리·보존하고, 작품과 작가의 맥락을 참고사이트와 블로그로 연결하는 예술 아카이브.**

ARCH-B는 아트, 참고사이트, 블로그를 중심으로 운영한다. 아트는 실제 작품을 작가별로 수집하는 공간이고, 참고사이트는 탐색에 도움이 되는 외부 웹사이트를 선별한 디렉터리다. 블로그는 작품과 사이트를 바라보는 운영자의 감상·조사·수집 기록을 담는다.

첫 공개는 설치 없이 접근하는 반응형 웹으로 제공한다. 모바일에서는 작품 감상·저장·짧은 읽기를, PC에서는 많은 작품의 검색·조사와 운영자의 자료 관리를 편하게 만든다. 두 환경은 같은 콘텐츠와 계정을 사용하며 핵심 탐색 기능을 함께 제공한다.

아트의 핵심은 작품 수와 작가별 자료의 깊이, 정확한 출처와 지속적인 보존이다. 현재 수집한 30점은 자료 구조와 화면을 검증한 표본이며 서비스 공개 목표 수량이 아니다. 전체 아카이브를 축적하는 작업과 오늘의 작품·블로그를 편집하는 작업을 별도 주기로 운영한다.

소개 문구 제안: **“좋아하는 작품과 발견, 오래 남기고 싶은 이야기.”**

현재 사이트의 디자인과 기존 게시물은 기획의 제약으로 삼지 않는다. 이번 문서는 서비스 방향, 콘텐츠 체계, 기능과 실행 범위를 정의한다. 사이트 개편이나 데이터 공개를 완료했다는 의미는 아니다.

## 2. 기획 배경과 목표

작품 이미지는 저장했지만 작가와 출처를 잊거나, 참고할 사이트는 북마크했지만 왜 저장했는지 기억하지 못하는 상황을 해결한다. 글에서 발견한 작품과 사이트를 다시 찾기 쉽게 만드는 것도 목표다. 이 문제는 현재 서비스 이용자 조사를 통해 확인한 결과가 아니라 초기 검증 가설이다.

서비스가 제공할 가치는 다음과 같다.

- **감상**: 미술 지식이 없어도 작품 이미지와 짧은 설명으로 시작할 수 있다.
- **발견**: 관심 있는 작가·주제에서 다른 작품이나 외부 자료로 이어갈 수 있다.
- **맥락**: 작품의 정보, 사이트의 추천 이유, 글의 근거와 출처를 확인할 수 있다.
- **축적**: 마음에 든 작품·사이트·글을 저장하고 나중에 다시 꺼내 볼 수 있다.

아트를 가장 강한 첫 방문 계기로 삼되, 세 영역은 각각 목록과 상세를 갖는다. 세 가지 모두 독립적으로 탐색할 수 있고, 관련성이 있는 곳에서 서로 연결한다.

### 4.1 아트

작품 이미지와 작품 정보가 중심이다. 작품마다 지속적으로 유지하는 상세 주소를 갖고 오늘의 추천, 작가 목록, 컬렉션과 블로그가 그 작품에 연결된다. 수천~수만 점을 전제로 페이지를 나누어 불러오고 작가·시기·재료·소장처를 조합해 탐색한다.

기본 아카이브에는 작품명과 원문 제목, 작가 또는 미상 상태, 제작 시기, 재료·기법, 크기, 소장처, 출처, 이미지와 사용 근거를 기록한다. 원출처가 제공하지 않는 시기·재료·크기는 미확인 상태로 보존한다. 짧은 소개와 감상 포인트는 선별 작품에 추가하며, 모든 작품의 해설 완성을 공개의 전제로 두지 않는다. 이미지를 공개할 수 없는 작품은 명확한 안내와 원문 링크를 갖춘 자료 레코드로 제공할 수 있으며, 이미지 확보 작품 수와 별도로 집계한다.

작품 상세의 순서: **전체 이미지 또는 이미지 제공 상태 → 작품명·작가·시기 → 상세 정보와 출처 → 등록·갱신 정보 → 관련 작품·사이트·글.** 해설이 있는 작품에는 짧은 이야기와 감상 포인트를 추가한다.

작가별 정리와 독립 작가 페이지는 초기 필수 기능이다. 한글·원문 이름과 별칭, 확인된 기본 정보, 수집 작품 수, 이미지 확보 수, 기관별 수집 범위, 최근 추가 작품을 제공한다. 작품은 제작 시기·재료·소장처·연작별로 탐색할 수 있게 하되 근거가 없는 연작·시기 구분은 만들지 않는다. 서로 다른 미술관의 동일 작가는 내부 작가 식별자로 연결하고 각 기관의 식별번호도 보존한다. 이름이 비슷하다는 이유만으로 병합하지 않는다. ‘등록 작품 전체’와 ‘작가의 전작’을 구분한다.

작가 미상은 ‘알 수 없는 한 명’으로 처리하지 않고 작품의 확인 상태로 관리한다. 공동 제작, 공방, 귀속 추정이 있는 작품은 원출처의 역할과 표기를 남긴다. 작품의 제작자와 블로그 글의 작성자는 별개의 정보다.

초기 탐색은 작품명·작가·별칭 검색과 작가·제작 시기·유형·소장처·이미지 유무 필터를 제공한다. 사조·연작·주제는 정리된 데이터에 한해 추가한다. 필터와 정렬, 페이지 위치는 상세에서 돌아와도 유지한다. 작가 탐색은 이름 검색과 가나다·알파벳 색인으로 제공해 작가 수가 늘어도 이용할 수 있게 한다.

### 4.2 참고사이트

‘참고사이트’는 방문자가 이용할 콘텐츠 메뉴다. 프로젝트 제작자가 참고한 벤치마크 목록과는 역할을 구분한다. DailyArt나 Rijksmuseum처럼 두 역할에 해당하는 사이트는 방문자에게 어떤 도움을 주는지 다시 편집해 등록한다.

사이트 한 곳에는 이름, 주소, 한 줄 소개, 대표 이미지 또는 화면, 추천 이유, 주요 이용 목적, 분류, 지원 언어, 확인된 무료·유료 범위, 최종 확인일을 기록한다. 운영자가 직접 확인하지 않은 기능은 있다고 단정하지 않는다.

| 초기 분류 | 방문자의 목적 | 첫 등록 후보 |
| --- | --- | --- |
| 미술관·컬렉션 | 실제 작품과 소장 정보를 찾기 | The Met, Cleveland Museum, National Gallery of Art, e뮤지엄 |
| 감상·탐색 | 취향에 맞는 작품을 발견하기 | DailyArt, Rijksmuseum, Google Arts & Culture |
| 매거진·읽을거리 | 주제와 이야기를 통해 탐색하기 | 29Magazine |

한 사이트에는 주 분류 하나와 목적 태그를 붙인다. 사이트가 여러 역할을 하더라도 중복 게시하지 않는다. ‘이미지 다운로드 가능’과 ‘공개 사이트에 재사용 가능’은 서로 다른 정보로 기록한다.

목록 카드에서 이름·한 줄 설명·목적을 확인하고, 상세에서 추천 이유와 사용 팁을 읽을 수 있게 한다. 상세에는 ‘사이트 방문’ 버튼을 명확히 제공한다. 링크가 끊기거나 서비스가 바뀌면 안내와 확인일을 수정하고 추천 노출을 조정한다.

### 4.3 블로그

블로그는 운영자의 관점이 가장 선명하게 드러나는 영역이다. 자료에 관한 사실과 필자의 감상을 구분하고, 글에 등장하는 작품과 사이트는 해당 상세 페이지에 연결한다.

| 연재·분류 | 내용 | 첫 글 가제 |
| --- | --- | --- |
| 작품 노트 | 한 작품에서 관찰한 장면과 감상 | 사이프러스가 있는 밀밭을 오래 바라보기 |
| 작가 노트 | 수집한 작품들을 통해 살펴보는 작가 | 서로 다른 미술관에서 만난 반 고흐의 네 작품 |
| 사이트 노트 | 실제 사용한 사이트의 장점과 탐색 방법 | 미술관 공개 컬렉션에서 작품을 찾는 순서 |
| 수집 일지 | 주제 선정과 수집 과정의 기록 | 첫 30점을 고르고, 작가별로 묶기까지 |

위 글은 기획용 제목이며 아직 작성·발행하지 않았다. 첫 공개에서는 네 분류를 모두 독립 메뉴로 크게 노출하기보다 글의 분류로 사용한다. 비어 있는 분류는 탐색 메뉴에서 숨긴다.

글의 필수 정보: 제목, 요약, 작성자, 발행일·수정일, 본문, 대표 이미지, 분류, 인용·참고 출처, 관련 작품·사이트. 작품의 제작 시기와 글의 발행일은 구분한다.

## 5. 메뉴와 홈 구성

주 메뉴는 **아트 / 참고사이트 / 블로그**로 둔다. 홈은 로고로 이동하고 검색·보관함·계정은 공통 기능으로 제공한다. 작가별 보기는 아트 안에서 바로 접근할 수 있게 한다.

| 화면 | 구성 | 주 행동 |
| --- | --- | --- |
| 홈 | 오늘의 작품, 작가 소개, 추천 사이트, 최근 블로그, 주제 컬렉션 | 흥미로운 대상 하나 선택 |
| 아트 목록 | 작품 이미지, 검색, 작가·주제·유형 분류 | 작품 감상 시작 |
| 작가 목록·상세 | 이름·별칭 색인, 수집 범위, 작품 수와 이미지 확보 수, 연대·재료·소장처별 작품 | 한 작가의 작업을 조사하고 변화와 맥락을 비교 |
| 작품 상세 | 이미지, 작품 정보, 이야기, 출처, 연결 콘텐츠 | 감상·저장·다음 탐색 |
| 참고사이트 목록·상세 | 목적별 분류, 소개, 추천 이유, 원사이트 링크 | 사이트 선택·방문 |
| 블로그 목록·상세 | 글 요약, 분류, 본문, 출처, 연결 콘텐츠 | 읽기·후속 탐색 |
| 보관함 | 저장한 아트·사이트·블로그를 유형별로 보기 | 저장 자료 재열람·저장 해제 |

홈은 세 영역의 전체 목록을 반복하기보다, 운영자가 선정한 작품 1점·사이트 2~3곳·글 2~3편을 소개한다. 등록되지 않은 데이터로 숫자를 채우거나 공개되지 않은 글을 추천하지 않는다.

주제 컬렉션은 아트 중심의 편집 묶음으로 먼저 운영한다. ‘빛과 풍경’, ‘꽃과 사물’ 등 작품을 함께 감상할 이유를 적고 관련 블로그나 사이트를 곁들인다. 사용자의 개인 보관함과 에디터의 공개 컬렉션은 구분한다.

## 6. 세 영역을 연결하는 원칙

작품은 작품으로, 사이트는 사이트로, 글은 글로 한 번 등록한다. 같은 대상을 소개할 때 복제하지 않고 연결한다. 확인된 작가·소장기관·출처의 관계는 수집 과정에서 연결하고, 감상 주제나 블로그와의 편집 관계는 운영자가 지정한다. 대량 작품에 대한 모든 관계를 수동 편집할 필요는 없다.

| 연결 | 표시 문구 예시 | 연결 기준 |
| --- | --- | --- |
| 작품 → 작가 | 이 작가의 다른 작품 | 동일 작가 식별자 |
| 작품 → 참고사이트 | 이 작품을 소장한 미술관 | 해당 기관 또는 컬렉션과의 실제 관계 |
| 작품 → 블로그 | 이 작품을 다룬 글 | 글에서 해당 작품을 다룸 |
| 참고사이트 → 작품 | 이곳에서 수집한 작품 | 작품의 실제 제공처 |
| 블로그 → 작품·사이트 | 글에 등장하는 작품 / 참고한 사이트 | 본문에서 언급·활용한 대상 |

관련성이 없는 콘텐츠를 억지로 연결하지 않는다. 연결할 항목이 없으면 해당 섹션을 숨긴다. 콘텐츠가 비공개로 바뀌면 공개 화면의 연결에서도 제외한다.

### 대표 이용 흐름

**짧게 감상하는 방문자:** 홈의 오늘의 작품 → 작품 이미지 확대 → 작가별 작품 보기 → 마음에 드는 작품 저장.

**자료를 찾는 방문자:** 참고사이트에서 ‘미술관·컬렉션’ 선택 → Cleveland 소개 읽기 → 해당 기관에서 수집한 한국 작품 확인 → 원사이트 방문.

**글로 유입된 독자:** ‘첫 30점을 고른 과정’ 블로그 → 글에 등장하는 작품 상세 → 같은 작가의 작품 → 보관함에 저장.

**작가를 조사하는 방문자:** 작가 이름이나 별칭 검색 → 작가 아카이브 → 시기·재료·소장처로 좁히기 → 작품 비교·저장 → 원출처와 관련 글 확인.

**운영자:** 기관별 자료 일괄 수집 → 원자료 보존 → 중복·작가·이미지·사용 근거 검증 → 예외 검토 → 기본 자료 공개 → 일부 작품 해설·블로그 편집 → 변경분 반영과 보존 상태 확인.

## 7. 최소 공개 버전의 기능

### 첫 공개에 포함

| 영역 | 기능 | 완료 기준 |
| --- | --- | --- |
| 아트 | 실제 작품 목록·상세·확대 감상 | 출처를 확인한 이미지와 작품 정보가 동일한 작품에 연결됨 |
| 작가 | 독립 작가 아카이브·별칭 검색·수집 범위·작품 목록 | 기관별 동일 작가 연결, 시기·재료·소장처 필터, 미상·귀속 추정 구분 |
| 참고사이트 | 목적별 목록·소개·원사이트 이동 | 추천 이유와 최신 확인일이 있고 외부 링크가 정상 동작함 |
| 블로그 | 목록·본문·분류·연결 콘텐츠 | 운영자가 글을 작성·수정·공개할 수 있고 관련 작품·사이트로 이동 가능 |
| 발견 | 오늘의 작품과 운영자 추천 | 운영자가 실제 공개 콘텐츠 중에서 선정 가능 |
| 검색 | 각 영역에서 이름·제목 검색 | 아트는 한글·원문 작가명과 작품명으로 찾을 수 있음 |
| 저장 | 세 유형 저장·해제·보관함 | 다시 방문해도 저장 상태가 유지되고 유형별 재열람 가능 |
| 수집·보존 | 기관별 일괄 수집, 실패 재개, 변경 감지, 파일·원자료·수정 이력 보존 | 같은 배치를 재실행해도 중복이 생기지 않고 수집·변경·실패 내역을 확인 가능 |
| 운영 | 자료 검증과 편집 상태 분리, 예외 검토, 공개·비공개 상태 | 미검증 자료는 대기하고, 해설 없는 검증 자료는 아카이브로 공개 가능 |

감상과 검색은 로그인 없이 가능하게 한다. 여러 기기에서 이어 쓰는 저장은 로그인한 계정을 기준으로 제공하는 안이다. 비회원의 저장 버튼은 로그인을 안내하고 기존 감상 위치로 돌아올 수 있게 한다. 로그인 방식은 기존 계정 기능 점검 후 확정한다.

### 이용 수요를 확인한 뒤 확장

개인 컬렉션 이름과 메모, 통합 검색, 관심 작가 구독, 뉴스레터, 색상 탐색은 후속 범위다. 댓글·커뮤니티, 사용자 공개 업로드, 자동 개인화 추천, 작품 거래는 초기 개발에 포함하지 않는다.

## 8. 콘텐츠 정보와 운영 기준

구현 전에 확정할 최소 정보 관계는 다음과 같다. 아래는 개념 정의이며 데이터베이스 변경안이나 실제 마이그레이션이 아니다.

| 대상 | 기준 정보 | 관계 |
| --- | --- | --- |
| 작품 | 고유 ID, 원문·한글 제목, 제작 시기, 이미지, 소장품 번호, 출처·이용 근거 | 한 명 이상의 작가, 주제, 제공 사이트 |
| 작가 | 내부 ID, 표시명·별칭, 원자료 식별자, 확인된 정보 | 여러 작품; 글 작성자와 구분 |
| 참고사이트 | 고유 ID, 대표 URL, 이름, 소개, 분류·목적, 최종 확인일 | 수집 작품, 관련 블로그 |
| 블로그 | 고유 ID, 제목, 작성자, 본문, 발행 상태와 날짜 | 여러 작품·사이트 |
| 에디터 컬렉션 | 제목, 설명, 공개 상태, 항목 순서 | 여러 작품과 선택적인 읽을거리 |
| 저장 | 이용자, 콘텐츠 유형, 대상 ID, 저장일 | 동일 항목 중복 저장 방지 |

모든 콘텐츠에 공개 상태와 수정일을 두고, 삭제 대신 비공개 전환으로 관계를 보존할 수 있게 한다. 작품별 소장품 번호는 기관과 함께 사용한다. 같은 제목의 서로 다른 작품이나 판본을 자동으로 합치지 않는다.

작품 레코드에 연결된 원출처 레코드, 이미지 파일과 해시, 수집 배치, 변경 이력을 보존한다. 원출처의 값과 내부 정리값은 구분하고 갱신 시 이전 값과 변경 이유를 남긴다. 작품 통합·분리도 되돌릴 수 있어야 한다. 상세 기준은 [대규모 작품 아카이브 운영안](art-archive-plan.md)을 따른다.

외부 이미지는 개별 사용 근거와 출처를 남긴다. 블로그에서 이미 등록된 작품을 사용할 때는 동일 자료를 참조한다. AI로 만든 참고 이미지를 실제 수집 작품으로 등록하지 않는다. 자동 요약을 이용하더라도 이름·연도·인용·작가 귀속은 원자료와 대조한다.

참고사이트의 링크와 무료·유료 범위는 월 1회 점검을 초기 운영 기준으로 제안한다. 이는 자동 점검 설정을 생성했다는 의미가 아니다.

## 9. 현재 확보한 자료와 첫 공개 목표

| 영역 | 현재 상태 | 첫 공개 전 준비 |
| --- | --- | --- |
| 아트 | The Met 8점·Cleveland 22점, 총 30점의 검증 표본 | 1,000점 일괄 수집 검증 후, 이미지·기본 정보가 확보된 5,000점 수준을 첫 공개 목표로 제안 |
| 작가 | 확인된 19명과 작가 미상 4점 분류, 별도 검토 페이지에 작가별 탐색 구현 | 작가 100명 이상을 초기 목표로 제안하고, 우선 작가 20명은 작가당 20점 이상 확보 가능성을 조사 |
| 참고사이트 | 8개 사이트의 역할·수집 가능성·확인 범위를 문서로 조사 | 방문자용 소개 8건 작성, 분류·대표 이미지·링크 확인 후 등록 |
| 블로그 | 이 기획을 위한 신규 원고는 아직 없음 | 작품·작가·사이트·수집 기록을 다루는 글 총 4편 작성 |
| 테마 | 검토용 4개 테마로 작품 분류 | 공개용 컬렉션 2개와 선정 이유 편집 |

작품의 고해상도 파일은 보관 자료다. 실제 서비스에서는 원본과 화면용 이미지를 구분해 목록의 용량을 줄이고, 확대 감상 시 더 큰 이미지를 제공하는 방안을 적용한다.

수량은 사용자에게서 지정받은 확정치가 아닌 규모 제안이다. 이미지 이용 조건, 기관별 자료 범위, 작가별 실재 작품 수를 조사해 조정한다. 먼저 1,000점으로 수집·검색·작가 통합을 검증하고, 5,000점 공개 이후 10,000점 이상으로 지속 확장한다. 없는 작품이나 중복 판본으로 목표 수를 채우지 않는다. 미상 작품은 작가 수에서 제외하고 이미지 없는 레코드는 이미지 확보 수에 포함하지 않는다. 모든 작품의 개별 해설을 쓰는 일정은 대량 수집 일정과 분리한다.

기존 사이트의 갤러리·참고사이트·블로그 및 계정·관리 기능은 재사용 후보이다. 작동과 데이터 적합성은 구현 전 점검해야 한다. 특히 기존 갤러리의 콘텐츠 유형을 실제 미술 작품과 같은 것으로 가정하지 않는다. 기존 데이터는 목록과 변경 영향을 확인한 뒤 유지·분리·이관 방향을 결정한다.

## 10. 제작 순서와 단계별 공개 기준

대량 수집과 보존 요구를 반영해 기존 4주 초안을 단계별 통과 기준으로 변경한다. 1,000점 시험 수집에서 처리 속도, 오류율, 저장 용량, 수작업 검토량을 측정한 뒤 일정을 산정한다.

| 단계 | 우선 작업 | 산출물·통과 기준 |
| --- | --- | --- |
| A: 수집·보존 구조 검증 | 30점 원자료 재활용, 작가 식별·중복 기준, 원본과 수정 이력, 기관별 수집 방식 | 재수집해도 중복되지 않고 실패 재개·백업 복원을 확인 |
| B: 1,000점 시험 운영 | 일괄 수집·검증, 작가 병합 예외, 이미지 크기별 제공, 검색·페이지 분할 | 처리 시간·저장량·오류·수동 검토량을 측정하고 확대 일정 산정 |
| C: 작가별 깊이 확보 | 우선 작가별 여러 기관 조사, 5,000점 수준 확장, 작가 전용 화면 | 공개 작품 수·이미지 확보 수·작가 수를 별도 검증하고 수집 범위를 표시 |
| D: 세 영역 연결 및 공개 | 참고사이트 8건·블로그 4편, 홈·저장, 실제 수량으로 모바일·검색·링크 검토 | 아카이브와 편집 콘텐츠의 전체 이용 흐름 확인 |
| E: 지속 확장 | 10,000점 이상으로 확장, 변경분 반영, 누락·오류 보완 | 수집 결과와 보존 상태를 점검하면서 신규 작가·기관을 추가 |

일정이 부족하면 해설·추천 코너의 제작량을 조정한다. 작가별 정리, 출처, 대량 탐색과 보존은 핵심 범위로 유지한다. 외부 서비스의 접근 한도와 공개 자료 범위에 맞춰 수집량과 간격을 조정한다. 자동 수집의 실제 구현과 정기 실행 설정은 후속 개발 작업이다.

## 11. 공개 전 확인 사항

- 공개 대상 전체에 식별자·출처·작가 연결 또는 미상 상태·이미지 제공 근거가 있고, 작업용 번역과 검토 완료 표기가 구분되는가?
- 전체 자동 검증과 기관·작가·유형별 표본 검토, 예외 건 검토를 마쳤는가?
- 재수집·작가 통합·원출처 변경·이미지 제공 중단에 대해 중복 방지와 이력·공개 상태 처리를 확인했는가?
- 원자료와 이미지 백업을 실제로 복원하고 파일 무결성을 확인했는가?
- 실제 공개 목표 규모에서 검색·필터·페이지 이동을 검증하고 30점 검토 화면의 방식과 구분했는가?
- 작가 미상·추정 연대·공동 제작 정보를 임의로 단정하지 않았는가?
- 작가 필터의 작품 수가 실제 공개 작품 수와 일치하는가?
- 작품 감상 중 이미지가 잘리거나 모바일에서 가로 스크롤이 발생하지 않는가?
- 검색어·필터를 바꾸고 초기화했을 때 결과와 안내가 일치하는가?
- 참고사이트 8곳의 소개·대표 URL·마지막 확인일이 실제 확인 내용과 일치하는가?
- 블로그 4편의 이미지·인용·출처와 관련 작품·사이트 연결을 확인했는가?
- 비공개 항목이 목록·검색·연관 콘텐츠에 나타나지 않는가?
- 저장·해제·재로그인 후 보관함 재열람과 키보드 조작을 확인했는가?

## 14. 실행을 위한 결정 사항

### 서비스 구성과 주소

상단의 핵심 메뉴는 아트·작가·참고사이트·블로그다. 작가는 아트의 핵심 탐색 방식이지만 바로 접근할 수 있는 메뉴로 노출한다. 보관함과 로그인은 계정 메뉴에 둔다. 기존 디자인을 답습하지 않고, 실제 작품의 비율을 보존하는 감상 화면과 많은 자료를 찾기 쉬운 목록을 기준으로 설계한다.

| 주소 기준안 | 역할 | 첫 공개 필수 동작 |
| --- | --- | --- |
| `/` | 편집된 발견의 입구 | 오늘의 작품, 작가 한 명, 사이트·글 추천, 아카이브 진입 |
| `/art` | 전체 작품 탐색 | 검색·필터·정렬·페이지 이동, 정확한 공개 수량 |
| `/art/[id]` | 작품의 고정 기록 | 이미지 확대, 정보·출처·갱신일, 작가와 관련 자료 연결 |
| `/artists` | 작가 색인 | 한글·원문·별칭 검색, 가나다·알파벳 색인, 수집 수량 |
| `/artists/[id]` | 작가 아카이브 | 수집 범위·확인된 소개, 작가의 작품과 조건별 탐색 |
| `/references` 및 상세 주소 | 참고사이트 디렉터리 | 목적별 검색, 방문자용 소개, 원사이트 이동; 기존 상세 주소 점검 후 유지 |
| `/blog` 및 기존 상세 주소 | 감상과 조사 기록 | 분류·연재, 관련 작품·사이트·작가 연결 |
| `/mypage` | 개인 보관함 | 아트·사이트·글 저장과 페이지별 재열람 |
| 기존 관리 영역 내 아트 메뉴 | 수집·검증·편집 운영 | 배치 상태, 예외 처리, 공개 상태, 수정 이력 |

### 기술과 기존 자산 활용

현재 저장소에서 확인한 Next.js·React·Supabase 기반을 활용하는 것을 기본안으로 한다. 블로그 편집기·참고사이트·인증·관리 화면을 점검해 재사용한다. 기존 갤러리는 생성 이미지·디자인 분류 중심이므로 작품·작가를 위한 독립 자료 구조와 `/art` 경로를 추가한다. 기존 데이터나 주소는 실제 목록과 유입을 확인해 개별 이관 여부를 기록한다. 관련 없는 기존 이미지 주소를 작품으로 일괄 연결하지 않는다.

수집은 사용자 웹 요청과 별개로 실행하는 배치 작업으로 만든다. 첫 단계는 기존 Node 수집 스크립트를 보완하고 실행 상태를 데이터베이스에 남기는 방식으로 시작한다. 외부 검색 서비스나 별도 큐 시스템은 시험 수집·성능 측정에서 필요성이 확인될 때 도입한다. 대량 원본은 저장소의 Git 이력에 추가하지 않고 파일 저장소에서 관리한다.

실제 운영 DB 스키마·권한 정책·저장소 요금제·배포 환경은 이번 문서 작업에서 점검하지 않았다. 해당 사항은 작업 계획의 첫 단계 산출물로 확정한다. 현재 화면과 로컬 표본을 근거로 운영 준비가 완료되었다고 판단하지 않는다.

### 데이터 상태와 역할

검증 상태는 `대기 → 검토 필요 또는 통과`, 공개 상태는 `초안 → 공개 → 비공개`, 해설 상태는 `없음 → 작성 중 → 검토 완료`로 독립 관리한다. 기본 정보와 이용 근거가 검증된 작품은 해설 없이 공개할 수 있다. 이용 근거가 확인되지 않은 이미지는 공개하지 않으며, 데이터 자체의 공개 가능성을 확인한 경우에만 이미지 없는 자료로 안내한다. 공개 숫자에는 실제 공개 자료만 포함한다.

| 역할 | 가능 범위 |
| --- | --- |
| 방문자 | 공개 작품·작가·사이트·글 탐색 |
| 로그인 이용자 | 방문자 기능과 본인의 저장·해제·보관함 이용 |
| 편집자 | 허용된 콘텐츠 작성·수정, 작품 해설·번역·연결 편집; 발행 권한은 기존 역할별 정책과 대조해 설정 |
| 아카이브 관리자 | 검증 통과·작가 병합과 분리·공개와 중단·수집 배치 운영 |
| 시스템 운영자 | 배포·비밀정보·저장소·백업 복원 관리 |

역할은 책임의 구분이며 인원 채용이나 신규 계정 생성을 뜻하지 않는다. 한 사람이 여러 역할을 맡을 수 있다. 기존 admin·subadmin·editor 역할을 임의로 바꾸지 않고 실제 권한표에 매핑한다.

### 첫 공개에서 제외하는 범위

개인 컬렉션 편집, 관심 작가 알림, 뉴스레터, 색상 검색, 댓글, 공개 업로드, 거래는 후속 단계로 둔다. PWA 설치 기능과 iOS·Android 전용 앱도 첫 공개 범위에서 제외한다. 첫 공개에서 필요한 것은 충분한 작품, 작가별 정리, 안정적인 검색과 감상, 출처와 보존, 참고사이트·블로그의 연결이다. 디자인 시안과 모든 작품의 장문 해설 제작은 이 기획 문서의 완료 조건에 포함하지 않는다.

## 15. 웹 우선 출시와 앱 확장 전략

### 15.1 웹을 먼저 만드는 이유

현재 서비스의 우선 과제는 작품·작가 자료의 확보, 정확한 정리, 탐색과 보존이다. 작품·작가·블로그가 고유 주소를 갖는 웹은 외부 링크에서 바로 감상과 조사로 이어지는 진입점을 만들기 적합하다. 검색엔진이 발견할 수 있는 공개 페이지와 내부 링크를 구성한다. 검색 노출과 유입은 실제 운영에서 확인할 지표이며 보장되는 성과는 아니다. 근거: [Google 검색의 링크 가이드](https://developers.google.com/search/docs/crawling-indexing/links-crawlable).

웹으로 자료 탐색과 운영을 먼저 완성하면 현재 저장소의 블로그·참고사이트·계정 기능을 활용하면서 수집·작가 정리·품질 검증에 개발 역량을 집중할 수 있다. 앱을 처음부터 함께 만드는 일정과 비용은 현재 제작 공수에 포함하지 않는다.

### 15.2 기기별 이용 경험

| 환경 | 우선 경험 | 필수 기준 |
| --- | --- | --- |
| 모바일 웹 | 오늘의 작품 감상, 이미지 확대, 작가의 다음 작품, 저장, 글 읽기 | 작품 비율 유지, 터치 조작, 접고 펼치는 필터, 읽기 편한 본문, 뒤로 가기와 로그인 후 위치 복귀 |
| PC·태블릿 웹 | 다수 작품 탐색, 작가·시기·재료·기관 조사, 출처 확인 | 화면에 맞는 목록 밀도, 키보드 조작, 필터 상태 유지, 작품·작가·원문을 주소로 재열람 |
| 운영용 웹 | 수집 배치 확인, 예외 검토, 작가 정리, 원고 편집, 공개·중단 관리 | PC에서 집중 작업하기 편한 목록과 원자료 대조, 변경 이력과 권한 확인 |

모바일과 PC의 기능을 별개 서비스로 나누지 않는다. 검색·필터·작가 탐색·사이트·블로그·보관함은 두 환경 모두 제공한다. 대용량 자료 검수와 일괄 편집은 PC 운영 화면을 우선 최적화한다. 반응형 웹을 만들었다는 이유만으로 설치나 오프라인 이용까지 제공한다고 표시하지 않는다.

### 15.3 단계별 플랫폼 범위

| 단계 | 구현·검토 범위 | 다음 판단에 필요한 증거 |
| --- | --- | --- |
| 1: 웹 첫 공개 | 반응형 웹, 작품·작가 고정 주소, 모바일 감상, 검색·저장·편집 운영 | 실제 공개 수량, 모바일·PC 이용 흐름, 품질·성능·복원 검증 |
| 2: 웹 운영 개선 | 첫 30일 지표·관찰과 이용자 요청으로 탐색·저장 개선 | 반복 방문과 보관함 재열람, 주요 기기·브라우저, 반복되는 이용 불편 |
| 3: 설치형 웹 검토 | 홈 화면 실행이 유용한 이용 패턴이면 PWA의 범위·지원 환경을 검증 | 설치와 재실행 요구, 대상 기기 지원 확인, 업데이트·캐시·로그아웃 동작 검증 |
| 4: 전용 앱 검토 | 위젯·오프라인 컬렉션 등 앱에서 제공할 경험의 시제품과 비용 비교 | 반복 수요, 웹/PWA에서 충족하지 못한 요구, 유지보수 여력과 구체적 검증 결과 |

PWA는 지원 환경에서 홈 화면 등에 설치해 실행할 수 있는 웹 방식이며 설치 절차와 지원 범위는 기기·브라우저에 따라 다르다. 오프라인·알림은 필요한 범위를 따로 설계·검증한다. 근거: [PWA 설치 안내](https://web.dev/learn/pwa/installation).

PWA와 전용 앱은 반드시 차례로 모두 만드는 일정이 아니다. 실제 요구에 따라 웹 유지·PWA 추가·전용 앱 시제품 중 하나를 선택할 수 있다. 작품 수가 10,000점에 도달했다는 사실만으로 앱 개발을 시작하지 않는다. 앱스토어 등록·위젯·알림·오프라인 기능은 향후 범위가 정해졌을 때 별도 계획과 공수로 산정한다.

### 15.4 향후 앱에서 공유할 기반

작품·작가의 영구 ID, 출처와 이미지 상태, 계정별 저장 기록, 공개 권한을 서버의 공통 기준으로 유지한다. 화면은 이 기준을 조회·표시하고, 수집과 검증은 화면에서 분리한다. 앱을 만들더라도 동일한 작품과 계정에 연결하고 별도의 작품 DB를 복제해 운영하지 않는 것을 원칙으로 한다.

첫 단계에서는 웹 기능에 필요한 데이터 접근과 권한부터 구현한다. 앱용 API 전체나 별도 앱 프레임워크를 미리 구축하지 않는다. 전용 앱을 검토할 때 로그인 세션·고정 웹 주소 연결·저장 동기화·오프라인 자료 갱신과 제공 중단을 추가 설계한다.

### 15.5 플랫폼 확장 판단 절차

공개 후 첫 30일 보고서에 기기별 반복 이용, 저장 후 재열람, 실제 기능 요청과 표본 수를 기록한다. 이용자가 적어 판단이 어려우면 웹을 개선하면서 관찰 기간을 늘린다. 설치·오프라인·위젯 중 해결할 요구가 구체화되면 작은 시제품으로 주요 기기에서 확인하고 구현·운영 비용을 비교한다. 결과와 선택 이유를 실행 계획에 남긴 뒤 해당 범위만 추가한다.
