# 뉴스 구성과 발행 원고 리뉴얼

상단 요약과 핵심 항목에서 결론을 먼저 전한다. 본문은 배경, 주제별 설명, 짧은 정리, ARCH.B 의견 순서로 이어진다. 관련 문단을 묶을 때만 내용을 설명하는 소제목을 쓰고, 도입과 정리는 제목 없이 둘 수 있다. ‘서론·본론·결론’을 소제목으로 쓰지 않는다.

충분한 근거가 있는 글은 2,600~3,600자를 목표로 설명한다. 발행 검증 범위는 900~4,000자다. 목표 분량을 채우려고 사실을 반복하거나 수치·효과·직접 취재 경험을 만들지 않는다. ARCH.B 의견은 브랜드를 다시 소개하는 문장 없이 판단과 이유부터 쓴다. 출처는 맨 아래에 중복 없이 모으며 본문에 자료 번호를 반복하지 않는다. 추가 이미지는 이번 리뉴얼에 포함하지 않는다.

## 2026-10-30 발행 원고 일괄 편집

발행 뉴스 719편의 기존 사실·수치·발표 시점과 원출처·공식 자료 연결을 유지하면서 문장과 구성을 편집했다. 초기 작업에서 생성·대조한 원고 480편과 직접 정리한 원고 239편을 사용했으며 각 편의 편집 방식은 결과 보고서에 기록했다. 추가 외부 AI 호출은 중단했다. 직접 편집에서는 기존 설명을 보존하고 기사별 정리 문장을 새로 쓰며 의견을 마지막으로 모았다. 충분한 내용이 있는 글을 보강하되 분량을 채우기 위한 새 사실을 추가하지 않았다. 이 검수는 새 취재나 원문 전체의 재검증을 의미하지 않는다.

작업은 발행 뉴스의 고정된 ID 목록을 대상으로 한다. 미발행 초안은 대상에 넣지 않는다. 원본과 검토 결과는 로컬 `research/news-backlog-2026-10-30-renewal/`에 보관하며 중단 후 이어갈 수 있다. 저장 중인 결과는 임시 파일에서 원자적으로 교체한다.

확인된 결과는 평균 2,723자(1,886~3,929자)다. 도입과 정리는 제목 없이 두고, 기존 설명을 억지로 합치지 않아도 되도록 발행 범위는 3~8개 섹션으로 조정했다. `scripts/news-direct-edit.mjs`는 직접 검토한 문단을 배치하는 로컬 도구이며 외부 API나 DB를 호출하지 않는다.

SQL 준비 CLI(`npx tsx scripts/prepare-news-renewal.mjs`)는 DB를 변경하지 않는다. 모든 대상의 검증이 끝나야 2편씩 묶은 트랜잭션 SQL을 만든다. SQL은 기존 제목·요약·본문 해시·보호 필드 해시가 모두 일치할 때만 제목·요약·본문·핵심 항목과 실제 수정 시각을 바꾼다. URL, 이미지, 태그, 작성자, 발행 상태·발행일과 나머지 콘텐츠 필드는 보존한다. 작업 중 다른 편집이 있으면 해당 배치를 중단하며, 이미 같은 결과가 반영된 원고는 수정 시각도 다시 바꾸지 않는다. 되돌릴 때 사용할 SQL도 로컬 rollback 폴더에 생성하며, 이후 편집이 없을 때만 이전 원고를 복구할 수 있다. 미발행 초안 71편은 변경하지 않는다.

대상별 제목, 분량, 소제목, 출처 수와 검토 시각·해시는 `content/news/renewal-2026-10-30.json`에 기록한다. 원본 및 전체 검토 원고는 로컬 백업에서 확인할 수 있다.

최종 반영 후 719편의 제목·요약·본문·핵심 항목이 준비된 원고와 정확히 일치하고, 이미지·출처·태그·작성자·발행 상태·발행일과 나머지 콘텐츠가 보존됨을 확인했다. 미발행 초안 71편도 변경되지 않았다. PC 1,440px와 모바일 390px에서 소제목·의견·하단 출처와 가로 넘침을 확인했으며 뉴스 공개 경로·편집 권한·파이프라인·SEO 검사 및 프로덕션 빌드를 통과했다.

npx tsx scripts/check-news-renewal.mjs
npx tsx scripts/check-news-reading.mjs
npx tsx scripts/check-news-pipeline.mjs
npx tsx scripts/check-seo-discovery.mjs
